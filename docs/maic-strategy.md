## 0. 一句話結論(先看這個)

LumaStage 已經精準命中本屆 MAIC 的**技術風口**(visionOS 空間運算 1:1 沉浸 + 裝置端音樂理解 + 由 OpenAI 雲端模型生成整套專業 rig),技術深度與完成度足以同場競爭。**但要拿「最具創新獎」,缺的不是更多炫技,而是三塊拼圖:**

1. **可信度**:從「寫死兩個 cue」升級成真正的 **cue 序列 + 動態效果**(目前任何懂燈光的評委一眼會看穿這不是設計工具)。
2. **社會價值敘事**:歷年最高獎幾乎全是「最新 Apple 技術 + 真實社會痛點(尤其無障礙/教育公平)」——這是啟航賽道 20 分、且設有 **60% 單項淘汰硬門檻**的維度,目前 LumaStage 近乎空白。
3. **閉環到真實世界**:把已經寫好卻是死碼的 `DMXPatch` 撿起來,匯出**燈位圖 / Patch Sheet**,證明「這不是虛擬玩具,是進場前真的用得上的工具」。
   > **狀態更新(2026-07-07)**:A2 配接表匯出**曾實作、後決定下架移除**(功能與 UI 已刪;`DMXPatch` 資料欄位保留,見 `docs/specs/README.md` 現況基線的「移除」條目)。本文其餘 A2 / Patch Sheet 段落(§2 體檢、§3 A2、§6 時程、§8 速記)一律視為歷史提案——**決賽不得宣稱可匯出配接表**;「閉環真實世界」敘事改走「未來以 Art-Net/sACN 當專業控台上游」的規劃性說法(`social-value.md` §5 已如此定位)。

**定位金句**:`LumaStage 是第一個 AI 原生的空間燈光設計工具 ——「你穿戴的那一台燈控台」。我們不是把控台搬進螢幕,而是讓你站進 1:1 的舞台數位孿生裡,用一句話,讓 AI 把整套專業燈光打出來。`

## 1. MAIC 評審情報與「得獎畫像」

> 來源:多方交叉佐證(appcontest.net 官網、浙大新聞、少數派十年回顧、各校官方通知)。**精確分數權重逐年微調,報名前務必以當屆官方《參賽指南》為準。**

### 1.1 賽制與流程
- **主辦**:全國高等學校計算機教育研究會 + 浙江大學 + Apple 聯合承辦;2025 為第十屆。
- **賽道(第十屆)**:啟明(創意提案)/ 啟迪(完整作品)/ **啟航(最高階、最高獎)**。
- **流程**:初賽(線上文件)→ 複賽(線上文件+影片)→ **決賽(現場公開答辯 + 路演 demo + 評委親手體驗 + Q&A)**。
- **賽區**:按七大賽區劃分,**無獨立「大中華區」晉級段**。台灣校隊以**個別隊伍**身分與大陸隊同場競技,近兩年已有先例得獎(2025 中原大學《VCook》啟迪一等獎、清華大學《Savers》社會責任獎)。→ **策略上請以「進入全國決賽、爭啟航賽道最高榮譽」為目標設定,並在報名前核對當屆官方賽區與賽道細則。**

### 1.2 評分維度與權重(這決定你把力氣花在哪)

- **硬門檻(啟明/啟迪明文,啟航實務同理)**:**每一項得分不得低於該項滿分的 60%,單項不達標即淘汰。** → **不能偏科**。創新再強,社會價值或商業前景掉到 60% 線下,直接出局。

### 1.3 得獎畫像(歷年最高獎/最具創新獎的共通 DNA)

> **最新 Apple 技術 × 真實社會痛點(尤其無障礙/教育)× 完成度接近上架。**

- 《謂爾》(2021,電子寵物促進心理健康)— 最具創新獎+一等獎
- 《妙手》(2024,聽障學生團隊做 AI 手語識別教學)— **最具創新獎+社會責任獎**,Tim Cook 點名稱讚
- 《心語》(2025,AI 輔助電話無障礙平台)— 啟迪特等獎

## 2. 以 grandMA2 視角的「燈光設計師體檢」

> 這一節用專業燈控台的工作流程,逐項檢查 LumaStage 站不站得住腳。**懂 MA2 的評委會用這張表看你。**

| 專業工作流程要素(grandMA2 / MA3) | LumaStage 現況(已核對程式碼) | 診斷 |
|---|---|---|
| **Patch(燈具→Universe/Address)** | `DMXPatch` 結構與 `validate()` 已寫好,但**「虛擬孿生忽略它」**,只有 `showcaseDemo()` 填值,**從未被使用/匯出** | 🟡 **死碼,撿起來就是分** |
| **Fixture Types(燈具型號庫)** | 10 種 `LightingFixtureVisualModel`(Fresnel/spot/moving head/PAR/strobe/blinder/laser…),各有光度學/光學/掛位元資料 | 🟢 夠用,概念正確 |
| **Groups(編組)** | 無顯式編組概念;AI 直接吐逐燈值 | 🟡 可後補 |
| **Presets / Palettes(Color/Position/Beam/Gobo 調色盤)** | 無。AI 每次生成都是絕對值,沒有可複用的 palette | 🔴 專業核心缺口(但可用「AI 即 palette 產生器」敘事繞過) |
| **Programmer(現場建構區)** | 對應的是「AI 生成 + 逐燈覆寫層 `LightOverride`」 | 🟢 有等價物,且更低門檻 |
| **Cue / Sequence / Cue List(走台表)** | **寫死恰好兩個 cue**(`cue_opening`+`cue_highlight`,`validate()` 強制兩者皆在,`@Generable` schema 也只產這兩個) | 🔴 **最傷可信度的硬傷** |
| **Executor / GO 鍵(串場播放)** | 無。只能在兩個 cue 間切換 | 🔴 沒有「一場秀」的概念 |
| **Cue Timing(每屬性 fade/delay/snap)** | 有單一 `CueTransition`(2.5s linear 交叉淡入),全燈齊變 | 🟡 有過場,但無分層時序 |
| **Effects Engine(正弦 pan/tilt、chase、phaser)** | **完全沒有**。`pan/tilt/beamAngle` 是**靜態欄位**,AI 連產都不產;strobe/laser 只是「亮起來」不會動 | 🔴 **第二大缺口、也是 AVP 最強 wow 的所在** |
| **Sound-to-Light / BPM Master(音樂同步)** | 無 | 🟡 高 wow 的延伸功能 |
| **Timecode(SMPTE/MIDI 觸發)** | 無 | ⚪ 賽前不必做 |
| **Fan / Align(值的展開)** | 無 | ⚪ 進階,可不做 |
| **DMX / Art-Net / sACN 輸出** | 無真實輸出 | 🟡 Patch Sheet 匯出是穩的 80% 價值;即時 Art-Net 風險高 |
| **3D 視覺化(MA 3D / Capture / Depence)** | **這正是 LumaStage 的強項**:真 RealityKit `SpotLight`、軟陰影、gobo 投影、可見雷射光束、1:1 數位孿生、雙沉浸(房間溢光) | 🟢🟢 **超越傳統 previz 的維度** |
| **逐燈精準控制(抓單一 channel 覆寫 cue)** | `LightCommand`/`LightOverride` 已實作:「把 Light 5 關掉」「第 3 盞變綠」疊在 AI 結果之上 | 🟢 **直接反駁「AI 不精準」** |

**體檢總結**:LumaStage 在**視覺化/previz 維度遠超傳統工具**(沒有任何控台能讓你站進 1:1 舞台、把整套燈光疊進你身處的真實房間),但在**設計流程的「時間維度」**(cue 序列 + 動態效果)上是退化的。補上時間維度,它就從「一張會動的燈光效果圖」變成「一個真的能設計一場秀的工具」。

## 3. 功能路線圖(為決賽 demo 無情排序,非兩年產品計畫)

> 排序原則:**S = 補最大評分缺口 + 最傷可信度硬傷;A = 最大 wow + 最低垂的果實;B/C = 錦上添花或現場風險高。**
> 標 🟡 者為「**撿現成**」(程式碼/素材已在,工作量被嚴重高估,CP 值最高)。

### Tier S —— 必做,動到根才補得起來

#### S1. 社會價值支柱 + 全語音無障礙模式 〔最高 CP〕
- **為什麼**:命中啟航 20 分(且 60% 硬門檻)的維度,正中歷年最高獎 DNA。把產品從「酷工具」重新定位為「**讓沒有器材、沒有場地、甚至視力/行動受限的學生劇團與獨立創作者,只靠一台 Vision Pro 就能設計專業舞台燈光**」。
- **🟡 你已有 80% 素材**:語音輸入(`SpeechTranscriber`)、AI 生成、`LightingExplanation` 白話教學。只缺**全程零觸控閉環**(語音生成 → 語音切 cue → 語音逐燈微調 → `AVSpeechSynthesizer` 朗讀 explanation)+ `accessibilityLabel`/Dynamic Type 標註。
- **MA2 對應**:對應的不是某功能,而是 **MA2 陡峭學習曲線本身**——專業控台要數週訓練+昂貴硬體,這個模式把入門降到「一句話」。
- **Apple 技術**:Speech(語音輸入)+(新增)AVSpeechSynthesizer(朗讀)+ App Intents(Siri/捷徑觸發,可選);燈光生成走 OpenAI 雲端。
- **工作量**:S/M(敘事+a11y 標註=S;全語音閉環=M)。風險低,主要是**重新包裝既有能力**。
- **誠實底線**:**只有真的做出無障礙模式才講無障礙**,否則只講「democratization」。評委會抓造假。

#### S2. 多 Cue 序列 + Cue Stack 播放(GO 鍵串場)
- **為什麼**:**最傷專業可信度的硬傷**。把「一句話生成一個 look」升級成「**描述整場演出 → AI 生成多段 cue 的走台表 → 按 GO 一段段走完**」。這是所有 cue 相關功能的地基,同時放大「一場完整的秀」的敘事。
- **MA2 對應**:Sequence / Cue List + GO 鍵 + cue fade time——燈控的核心心智模型。目前的兩個 cue 是它被砍到剩兩格的退化版。
- **Apple 技術**:`@Generable` 改成生成 cue 陣列(移除 `.count(4...12)` 與 `validate()` 的雙 cue 不變式雙鎖);RealityKit 既有 `withAnimation` 交叉淡入直接驅動逐 cue 過場。
- **工作量**:M/L。**改動深**:`validate()` 的雙 cue 不變式、`StageState`、iPad panel、smoke tests **都要動**(CLAUDE.md 明列這些是測試 pin 的不變式,務必同步更新測試)。風險:on-device 模型生成更長巢狀陣列的穩定度,需實機驗證 + mapping 修補。
- **實作順序**:先放寬 `validate()` 雙 cue → 改 `@Generable` 移除雙鎖 → 改 `StageState`/iPad panel → 更新 smoke tests。

### Tier A —— 最大 wow + 最低垂果實

#### A1. 動態效果引擎(Pan/Tilt 掃動 + Strobe + 色彩 Chase)
- **為什麼**:**AVP 沉浸式 demo 最直接的 wow**。靜態打光在截圖就看得到,**會掃動/閃爍的光束陣列只有戴上頭顯才震撼**——正中 Cook 對「新形態設備上的新體驗」的偏好。`dynamic-rig` 計畫已明文把動態留到後續,`showcaseDemo()` 也已備好 moving head/strobe/laser。
- **MA2 對應**:**Effects Engine**(Pan/Tilt 圖形如 Circle / Figure-8、Dimmer/Color Chase,phase/speed/size 參數)——MA2 最讓新手卻步、也最出效果的子系統。LumaStage 用「讓燈跟著節奏掃動」一句話取代繁複參數。
- **技術**:一個 `TimelineView` 或 RealityKit 系統每幀依 phase/speed/size 計算正弦 pan/tilt 與亮度脈動,寫進既有 `SpotLight` 方向/intensity。效果可由 OpenAI 生成時建議「要不要動 + 什麼效果」,或由確定性的音樂秀(`MusicShowBuilder`)依節拍指定。
- **工作量**:M。數學單純(正弦/相位),風險在 **8–12 盞燈即時更新 + 軟陰影的效能**(`dynamic-rig-plan` 已標此風險)。**建議只動方向/強度,先別動軟陰影**,必要時限制同時動態的燈數。

#### A2. 真實世界輸出:Patch Sheet / 燈位圖(Magic Sheet)PDF 匯出 〔撿死碼〕
- **為什麼**:把 LumaStage 從「虛擬玩具」變成「**進場前真的用得上的 previz 工具**」,直接服務商業前景(啟航 35 分)。敘事:「學生在宿舍用 Vision Pro 設計好,匯出一張紙,到場直接交給技師 patch。」——閉環到真實器材,是與「純螢幕 demo」作品的強差異化。
- **🟡 撿現成**:`DMXPatch` + `validate()` 已是現成死碼。寫一個 universe/address 自動分配器掃過 rig,再用 `ImageRenderer`/PDFKit 排出 Patch Sheet + 燈位圖(燈位 + 顏色/角色)。
- **MA2 對應**:grandMA2 的 Patch + 列印 Magic Sheet / Patch Sheet——演出前置的標準交付物。
- **Apple 技術**:純 Swift、完全 on-device、不需網路(呼應隱私敘事)。
- **工作量**:M,風險低(資料結構齊全)。**即時 Art-Net/sACN 輸出另計為 L + 硬體風險,不建議賽前做**。

#### A3. 雙沉浸「passthrough」demo 強化(已實作,確保鏡像投影下讀得出來)
- **為什麼**:一鍵從不透明夜舞台翻成 mixed passthrough,**評委回到自己的真實房間,而 AI 設計的 1:1 舞台與光束就疊在這個空間裡**——「只有空間運算做得到」的魔法時刻。
- **🟡 已實作**(`.full ↔ .mixed` immersionStyle 切換 + `.preferredSurroundingsEffect(.dim)`);**唯一要做的是:在實體裝置上驗證鏡像投影下這個切換讀得出來**,並在 demo 腳本固定這個高潮 beat。
  > **誠實 caveat(visionOS 26)**:此模式切換為 passthrough(可見真實房間)+ 環境調暗,虛擬舞台/光束/雷射與真實空間**疊加共存**;但「虛擬聚光燈**實際照亮真實牆面**」需 visionOS 27+ 的 `SpotLightComponent.SurroundingsLight`,本版尚不具備——**demo 台詞不要宣稱「光打在你的牆上」**,說「虛擬舞台疊進你的房間」。

## 4. 功能 → 評分維度映射(守住 60% 門檻的作戰圖)

### 5.4 評委硬問題 + 標準答案(練到能微笑、脫稿回答)

> **「這不就是個炫技玩具嗎?」**
> 玩具解決不了真實痛點——這個解決「**學燈控台要先有燈控台**」的死循環。一套入門器材+控台動輒數十萬,學生劇團/偏鄉/獨立創作者根本碰不到;我們把門檻降到一台頭戴裝置,且**對標可上架成品**(真實燈光詞彙、多 cue 走台 + GO、完整繁中在地化)。

> **「你們不就是套一層 OpenAI API 嗎?和直接用 ChatGPT 有什麼不同?」**
> 差別在**我們不是聊天包裝,是把模型變成一台燈控台的設計引擎**。① 我們用 OpenAI Responses API 的 **strict `json_schema` 結構化輸出**,強制模型吐出一份**結構正確、可驗證**的專業 rig——4–12 盞燈、多段有序 cue,再經 `LightingLook.validate()` 逐項把關(色彩 hex、亮度 0–1、光束角、standardNight 環境…),ChatGPT 給你的是一段文字,我們給你的是**能直接打上舞台的資料**。② 生成結果被**空間化**成 1:1 的 RealityKit 真實打光(軟陰影、gobo、可見雷射),站進去所見即所得——這是純聊天做不到的維度。③ **音樂→整場演出**這條旗艦流程的分析**完全在裝置端離線**完成(`MusicUnderstanding`),不上傳、不需金鑰。真正的技術含量在**領域建模 + 空間渲染 + 裝置端音樂理解**,不在那一次 API 呼叫——這正把我們和「純調雲端 API 聊天」的作品區隔開。

> **「真的燈光設計師會用嗎?」**(這題決定你在懂行評委心裡的分量)
> 會——但定位是**燈控台之前的設計層與 previz**。LD 最痛的是進場前無法把空間化的設計講清楚;我們讓他們在沒場地、沒掛燈時就 1:1 預覽,把試錯搬到進場前。**逐燈覆寫層**(「把 Light 5 關掉」)保留精準:**AI 給速度,設計師留控制**。最終演出仍交 grandMA2 執行,我們未來透過 Art-Net/sACN 當它的**上游**——**不取代燈控台,我們餵它**。

> **「商業模式?誰付錢?」**
> 兩條腿:**教育市場訂閱**(展演/戲劇/廣電科系教學工具,學生不必先買器材;社團與獨立創作者個人訂閱)+ **專業 previz 授權**(LD 與製作公司按專案/座席)。相較「一整套燈控台+器材動輒數十萬」的硬體門檻,訂閱模式的成本結構對使用者友善;燈光生成的雲端 API 成本可控(每次生成 token 有限、且可用配額/分級訂閱吸收),而**音樂→整場演出**這條高頻使用的流程在裝置端離線完成、不產生雲端費用。Apple 孵化基金提供孵化/投資/上架對接。

> **「模擬有多準?」**
> 物理上是**真打光**——真 RealityKit 聚光燈、軟陰影、光束角,不是貼圖;0–1 亮度映射成光度學流明、光束角映射成 cone 與陰影半影。**誠實說**:它還不是逐瓦特光度學模擬——但設計階段要的是「這感覺對不對」,不是流明計讀數;絕對精度的最終調校仍在真實場地,**這正是我們定位在設計層而非執行層的原因**。

> **「為什麼一定要 Vision Pro?iPad 不行嗎?」**
> 燈光是**空間的**,平面螢幕殺死它最重要的維度。站在 1:1 舞台中央才能判斷光有沒有打到臉、背光有沒有把人從背景分離、光束角夠不夠寬——小螢幕全靠猜。房間溢光更是只有透視頭顯做得到。**iPad 是同步遙控伴侶,不是替代品。** 空間運算不是包裝,是產品成立的前提。

### 5.5 團隊展示弧線(啟航 10 分,別輕忽)
問題定義(學燈控台要先有燈控台)→ 為何 Apple 最新技術是最佳解(空間運算 × AI 生成 × 裝置端音樂理解的交會點)→ 真實使用場景(學生劇團/偏鄉/獨立創作者/LD previz)→ roadmap(Art-Net 輸出、上架、Apple 孵化基金)。**善用繁中+英混講**呼應評委多元背景。

### 5.6 誠實底線(可信度護欄,不可越)
1. **不宣稱取代 grandMA2**(對業界評委瞬間失分)。
2. **沒做出無障礙模式就不講無障礙**。
3. **不宣稱瓦特級光度學精度**。
4. **不跑無法保證的現場生成**——永遠備好預生成 fallback。
5. 每一個被評委抓到的誇大,代價都遠超那句話本來想換的分。
