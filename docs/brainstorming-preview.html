LumaStage 企劃預覽

用 Apple Vision Pro 建立語音優先的 AI 舞台燈光設計、生成與沉浸式預演工具。

AI 設計為主，教育用來幫助溝通 v1 不做複雜控制台，使用者透過語音和 AI 對話來生成、修改與理解舞台燈光。

00

本週 MVP Core Experience

本週只聚焦一條 demo：使用者進入 1:1 夜間室外舞台數位分身，透過 Vision Pro 的懸浮 AI 對話框用真的 speech-to-text 說出需求，再送到 OpenAI API 生成 cue-based 燈光，最後用 iPad 微調目前 cue 的顏色與 dimmer。

進入舞台看見夜間室外學生舞台與基本燈具。
說出需求支援中英混講，例如「把 front light dimmer 降到 60%。」
OpenAI 生成回傳 selectedCueId、cues、fixtureGroups、transition 與 explanation。
iPad 微調調整目前 cue 的 front light dimmer 或 background wash color。
一句解釋用業界詞加白話說明這次調整。

本週要做

夜間室外舞台數位分身、standardNight 周邊環境光 baseline、Vision Pro 懸浮 AI 對話框、真實 speech-to-text、中英混講解析、OpenAI API cue-based 結構化生成、iPad 微調面板、基本燈具/顏色/dimmer。

本週不做

真實場地 AR 打光、iPad 完整編輯器、燈控台輸出、rigging/承重、室內窗戶日光、完整 cue timeline 編輯器、多使用者。

Demo 句子：進入 standardNight 夜間室外舞台 -> 語音轉文字 -> AI 解析中英混講指令 -> OpenAI API 產生 cue-based 燈光配置 -> 切換 cue 時用 animation 轉場 -> 用 iPad 微調目前 cue 的 dimmer 或 wash color -> AI 用聽得懂的方式解釋專業詞。
01

想解決的問題

LumaStage 的核心不是單純做一個舞台模擬器，而是先建立 1:1 夜間室外舞台數位分身，用固定的 standardNight baseline 讓使用者能清楚判斷 AI 生成的舞台燈光效果。

專業燈光師

問題不只是在電腦裡的預視和實燈效果不同，而是規劃前常常無法完整判斷現場光環境。等現場開燈後，亮度、光色和氛圍可能都和原本想像不同。

standardNight baseline

v1 不先比較多種夜間環境光。先固定 standardNight，讓舞台燈的亮度、顏色、對比和可讀性有一個可信但穩定的判斷基準。

學生與初學者

初學者除了缺少設備與場地，也常不知道怎麼把意圖說清楚。知道燈具名稱、顏色和電門後，才更容易和 AI 合作完成設計。

一句話：用 1:1 夜間室外舞台數位分身與 standardNight baseline，讓使用者在沒有完整設備、沒有真正進場的情況下，先看見 AI 生成的舞台燈光是否成立。
02

比賽主軸

目前主軸改為「AI 舞台燈光設計為主，教育作為溝通引導」。LumaStage 不是先做課程，而是讓使用者透過語音和 AI 共同生成、修改與理解舞台燈光。

AI 設計是主軸

使用者說出想要的舞台氛圍、場地條件與限制，AI 轉成可預覽、可修改的燈光設計，並立即在 Vision Pro 裡呈現。

教育幫助溝通

初學者學燈具名稱、顏色和電門，不是為了上完整課程，而是為了能更準確地跟 AI 說明自己想要的效果。

專業價值如何保留

同一套 AI 生成與沉浸預演能力，未來可以延伸到進場前的專業 previs，尤其是室外光環境、舞台比例和觀眾視角這類現場條件。

03

AI 舞台生成

使用者不需要從零手動排每盞燈，而是提供室外舞台照片、場刊或舞台圖、設備清單、想達成的氛圍與文字 prompt，讓 OpenAI API 在固定 standardNight 環境下生成可預覽、可微調的 cue-based 舞台燈光配置。

室外舞台照片、場刊、舞台圖或現場筆記，幫助 AI 建立 1:1 舞台數位分身。
夜間 ambientMVP 固定 standardNight，不先做 dark night 或 bright surroundings 切換。
目標效果例如溫暖開場與副歌/亮點 cue 的情緒差異。
OpenAI API回傳 selectedCueId、cues、fixtureGroups、transition 與 explanation。
沉浸預覽在 Vision Pro 中切換 Opening / Highlight，確認 cue animation、空間感與視覺層次。
04

MVP Lighting Look Schema

第一版 OpenAI structured output 描述一組小型 cue-based lighting look，不是完整燈控工程。這份 schema 讓 Vision Pro 預覽、iPad 微調、cue animation 和 AI 解釋共用同一份資料：selected cue、fixture group、顏色、dimmer / intensity、transition、固定 standardNight ambient baseline，以及一句能教使用者下次怎麼說得更精準的解釋。

總體用途

OpenAI 從語音 transcript 或 prompt 產生 cue-based 燈光 look；Vision Pro 套用 selected cue；iPad 微調目前 cue。

資料邊界

v1 先記錄可見的舞台光：固定環境光、cue、transition、燈具群組、顏色、亮度與解釋。不處理 DMX、完整 timeline editor、rigging 或真實燈具物理資料。

設計原則

每個 cue 和 fixture group 都要有穩定 id；iPad 控制和語音局部修改預設只改 selected cue，切換 cue 時用 animation 過渡。

05

V1 介面：AVP 預覽，iPad 微調

第一版介面要保持簡單：Apple Vision Pro 是沉浸式舞台與 AI 對話，iPad 是微調面板。語音要是真的 speech-to-text，並允許使用者在中文句子裡穿插 lighting terms。

Vision Pro：懸浮對話框

最少顯示 mic 狀態、transcript、AI understood command 和 explanation。不要先做完整控制台。

語音是主要輸入

使用者可以說「把主燈調暗」、「front light dimmer 降到 60%」、「background wash 改冷一點」、「讓舞台背景更暗」或「這盞燈是做什麼的」。

iPad：輕量微調

本週只做少數控制：front light dimmer、background wash color、reset。這些控制只調整 selected cue；完整編輯器和環境光切換留到未來。

建議 v1 工作流：進入沉浸舞台 -> 對 AI 說話生成 cues -> 切 cue 時用 animation 轉場 -> 用 iPad 微調 selected cue -> AVP 立即預覽變化 -> 得到一句簡短解釋。
06

可控的 AI 語音修改

Vision Pro 裡的語音修改需要同時支援兩種意圖：小範圍修改時像設計工具一樣保留已確認內容；使用者明確要求時，也能重新生成完整舞台方向。

可指定目標

例如後排燈、左側光束、某一段 cue、某個色彩組合或副歌段落。

可完整生成

例如「重新生成一個開場」、「用現有設備做演唱會版本」、「把整段結尾改成更戲劇化」。

技術含義

局部修改需要 patch selected cue；完整生成應該建立新版本。cue 之間切換時，用 transition duration 和 easing 做 animation。

07

AI 溝通引導

LumaStage 的教育重點不是獨立教學，而是幫使用者更會跟 AI 溝通。知道燈具名稱、顏色和電門/亮度後，使用者就能更準確地描述想要的舞台燈光。

知道燈具名稱

當使用者知道 wash、spot、front light 和 background wash，就能更精準地要求 AI 調整主視覺、補光、氣氛或背景層次。

用顏色描述意圖

AI 可以把「更溫暖」、「更冷」、「副歌更亮」轉成色彩與色溫調整，也能解釋夜間環境光為什麼會讓顏色看起來不同。

用電門控制程度

教學要保留 dimmer / intensity 這類業界詞，但同時用白話解釋成「燈有多亮、推到幾成」。使用者之後就能說「主燈降到 60%」。

目前決策

決策原因
英文 Markdown 保留為原始筆記方便持續整理，也讓 AI 更容易維持穩定結構。
比賽主軸採用 AI 舞台燈光設計為主核心價值是透過語音與 AI 共同生成、修改與預覽燈光；教育用來幫助使用者更會跟 AI 溝通。
AI v1 生成可編輯舞台配置比只看預覽更有產品感，但不過早承諾可直接上控台。
v1 採用 AVP 懸浮 AI 對話框 + iPad 微調語音和 AI 負責生成，iPad 負責少數精準微調，避免第一版變成複雜燈控台。
語音是主要輸入方式使用者透過說話生成、修改與理解燈光，文字輸入最多作為備援。
語音修改同時支援局部修改與完整生成小修改要避免誤動已確認內容；大修改則讓使用者能在 Vision Pro 內直接生成新的完整方向。
加入輕量 AI 溝通引導使用者知道燈具名稱、顏色和電門後，可以更準確地向 AI 描述想要的燈光效果。
v1 先聚焦 1:1 室外舞台數位分身室外舞台在學生活動中更常見，也比室內場地更容易完整查看，因此更適合作為第一個模擬案例。
iPad 微調屬於 Core Experience本週要做的是少數 demo 參數的穩定控制，不是完整 iPad 編輯器。
初學者先學燈具、顏色、電門這些基礎不是獨立課程，而是讓使用者能用更精準的語言跟 AI 溝通。
學生場景不假設 LED 螢幕學生活動通常不會有 LED 螢幕，因此 v1 demo 應該使用夜間室外舞台、周邊環境光和基礎燈具這類更常見的條件。
使用業界語言，但要講到初學者聽得懂保留 dimmer / intensity 等專業詞，並搭配「燈有多亮、推到幾成」這類白話解釋，讓使用者能真的拿去和 AI 溝通。
使用 OpenAI API 做 MVP AI 生成本週先用 OpenAI API 產生結構化燈光配置與簡短解釋，不先自建完整 AI 後端。
v1 語音採用真的 speech-to-text使用者可以中英混講；系統先保留 transcript，再由 AI 解析成可確認、可套用的燈光指令。
STT 失敗時用 typed prompt 備援主體仍然是語音優先；demo 當天如果麥克風或轉錄不穩，改用文字 prompt 接續同一條 AI 生成流程。
MVP schema 採用 Lighting Look Schema第一版描述 cue-based 可見燈光狀態：固定 standardNight ambient、cues、fixture groups、color、intensity、transition 與 explanation，先不做完整燈控工程資料。
夜間環境光 MVP 只做 standardNight本週不做 darkNight / brightSurroundings 切換，先把 AI 生成燈光與 iPad 燈具微調做穩。
Swift model 與 enum 直接對齊 schemaSwift 型別命名和 enum raw value 直接跟 OpenAI JSON 一致，減少生成、AppModel、iPad 控制與 RealityKit 渲染之間的轉換。
iPad 微調控制固定為三項第一版只做 front light dimmer、background wash color、reset，足夠展示 AI 生成後的精準微調，不先擴成完整編輯器。
燈光 look 改成兩個 cueMVP 只做 Opening 和 Highlight；iPad 微調只改 selected cue，兩個 cue 之間透過 transition animation 調整 intensity 與 color。
第一批燈具詞彙固定四個先用 wash、spot、front light、background wash，足夠讓初學者和 AI 溝通主要舞台光與背景層次。
懸浮 AI 對話框固定四個內容先顯示 mic state、transcript、AI understood command、explanation，讓語音流程可理解、可確認、可復原。
